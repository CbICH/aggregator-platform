# Воспроизводимая проверка блока B

Все файлы в этом каталоге относятся только к блоку тестирования и категории. Синтетические проверки не заменяют пилот с людьми.

| Артефакт | Назначение | Текущее состояние |
|---|---|---|
| `assessment-template-check.py` | 100 вариантов каждого из 18 шаблонов, детерминированность, отсутствие утечки эталонов и перенос ответов между вариантами | Пройдено, отчёт в `assessment-template-report.json` |
| `assessment-pilot/raw_results.csv` | Анонимизированные сырые строки добровольцев | Пустой шаблон, пилот не проведён |
| `assessment-pilot/metadata.json` | Версия форм, даты, способ независимой ручной оценки и исключения с обязательными причинами | Шаблон до начала пилота |
| `assessment-pilot/analyze.py` | Расчёт результатов A/B и сравнение с ручной оценкой | Вернёт `not_measured` до внесения строк |

## Генераторы

Из корня репозитория:

```powershell
$env:PYTHONPATH='apps/api'
.\.venv\Scripts\python.exe validation/assessment-template-check.py
```

Отчёт проверяет 1 800 вариантов (18 x 100) и по 20 переносов готовых ответов на другую форму в каждой из шести категорий. Он фиксирует фактическую долю успешного переноса, а не обещает абсолютную защиту от внешней помощи.

## Пилот с людьми

До внесения данных заполнить `assessment-pilot/metadata.json`: даты, версии форм, независимого оценщика и только реальные исключения с причиной для каждого кода. Затем заполнить одну строку `raw_results.csv` на добровольца. `participant_code` должен быть случайным кодом, без ФИО, email или других личных данных.

```powershell
Push-Location validation/assessment-pilot
python analyze.py --input raw_results.csv --metadata metadata.json --output report.json
Pop-Location
```

`report.json` создаётся только локально и не добавлен в Git. При пустом CSV он обязан содержать `status: not_measured`. После пилота сохраняются CSV, metadata, report и описанные ограничения; презентация не должна использовать целевые показатели как измеренные.
