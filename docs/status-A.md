## Результаты проверки

| Проверка | Результат |
|---|---|
| API и контракты, временный SQLite | 27 тестов пройдено |
| Те же проверки на отдельной PostgreSQL-базе `signal_test` | 27 тестов пройдено |
| Chromium, реальный API + PostgreSQL + SMTP Mailpit | 2 сценария пройдено: кандидат и работодатель |
| Alembic: миграция и сравнение моделей с PostgreSQL | Применена `0001_core`; `alembic check` не обнаружил новых операций |
| Ruff | Проверки и форматирование 33 Python-файлов пройдены |
| OpenAPI → TypeScript → production-сборка frontend | Генерация и сборка успешны |
| Docker Compose | Все четыре сервиса запущены и healthy |
| Визуальный просмотр страницы регистрации | Проверен локально в браузере |

Каждый браузерный сценарий проверяет регистрацию, получение настоящего локального письма, подтверждение email, вход, сохранение сессии после обновления страницы, выход и запрет доступа к кабинету после выхода.

Серверные тесты покрывают в том числе одноразовость и срок действия ссылок, конкурентное подтверждение, роли, CSRF, Origin, лимиты запросов, восстановление после ошибки SMTP, истечение и отзыв сессий, валидацию контрактов и отсутствие контактов в публичном DTO.

Есть одно предупреждение зависимостей: Starlette сообщает об устаревании адаптера TestClient для HTTPX. На результат тестов оно не влияет; обновление адаптера нужно выполнять вместе с совместимым набором зависимостей.

Workflow GitHub Actions подготовлен, но удалённый запуск CI не выполнялся. Производительность поиска, доменные сценарии B/C/D и внешний деплой пока не проверялись. Целевые метрики исходного плана не считаются результатами реализации.

## Передача B/C/D

1. Запустить стенд по [README](../README.md).
2. Использовать [инструкцию интеграции](integration.md), общие DTO, порты и фикстуры; подключать код в выделенные каталоги своих модулей.
3. Согласовывать изменения общих контрактов с A и регенерировать OpenAPI/TypeScript после изменения API.
4. После первого рабочего сценария каждого модуля вернуть A задачи A07 и оставшуюся часть A08 для сквозной проверки.
