## Ограничения и интеграция

До подтверждения категории B согласие на публикацию можно принять, но профиль не виден работодателям. После реального теста и подтверждения он становится доступен в списке D. Компания создаётся C через `/company`, сервер назначает `User.company_id`, D читает её через `SqlAlchemyCompanyRead`. До создания компании отправка закрыта (`COMPANY_REQUIRED`). Необязательный `need_id` пока отклоняется: таблицы потребностей C нет. ФСП показывает unavailable; его отсутствие не препятствует приглашению.

P1 вакансии/самостоятельные отклики, ATS и автоматическое распознавание PDF не реализованы. Настоящий B/C/D E2E уже проверяет тест B, компанию C и путь D; ранжированный подбор по потребности и ФСП C остаются вне этого сценария. FK к компании/потребности не добавлены; ownership проверяется портами. Удалённый CI нового кода не запускался; workflow запускает обычный BCD E2E и отдельный D E2E. Push не выполнялся.

Есть прежнее предупреждение Starlette о TestClient/HTTPX; тесты проходят. Повторяемый тестовый seed работает только на явно именованной test БД, не публикует synthetic подтверждения в рабочем приложении.

Дополнительный аудит: `test_d_contracts.py` проверяет актуальность всех D OpenAPI-операций, request/response/error/PDF, общую Salary, запрет лишних полей и обязательный timezone дат. `FspEvidence.fetched_at` также требует timezone. Seed использует фиксированное время и детерминированные UUID согласий/событий/grants; повтор сохраняет внесённые владельцем изменения и отзывы. T01/T02/P01/P02/P03 явно перечислены в фикстурах.
