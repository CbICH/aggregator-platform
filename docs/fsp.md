# Связь профиля с ФСП ID

MVP использует собственный синтетический реестр, разрешённый ТЗ. Интерфейс явно сообщает, что достижения демонстрационные. Это не подключение к реальной базе Федерации и не проверка владения реальным внешним ФСП ID.

## API и права

Кандидат с подтверждённым email читает `GET /api/v1/candidate/fsp`: статус, источник, сигнал, достижения, текущий ID и доступный ему `available_fsp_id`. `POST /candidate/fsp-link` принимает только `fsp_id`, требует CSRF и действующего согласия обработки профиля. Сервер сверяет ID с записью текущего аккаунта; чужой ID получает `422 FSP_ID_NOT_OWNED`. Результаты соревнований или баллы из запроса не принимаются. Повтор той же связи идемпотентен.

`DELETE /candidate/fsp-link` удаляет собственную связь, требует CSRF и работает даже при недоступности реестра. Связь хранится в `fsp_links`, имеет уникальный ID и FK к аккаунту. Audit содержит UUID кандидата без email/достижений.

Состояния: `not_linked`, `linked_empty`, `linked_with_data`, `unavailable`. При недоступности реестра связь сохраняется, данные не выдумываются, подбор остаётся доступен по тесту. Без истории ФСП кандидат проходит обычный путь публикации/приглашения. ID не раскрывается работодателю; публичная карточка показывает только источник, статус и демонстрационные достижения.

## Повторяемая демонстрация

| Подтверждённый адрес | История | Сигнал |
|---|---|---|
| `demo-fsp-winner@example.com` | Синтетический победитель | 100 |
| `demo-fsp-finalist@example.com` | Синтетический финалист | 60 |
| `demo-fsp-empty@example.com` | Пустая история | 0 |
| Любой другой адрес | Собственный пустой demo-ID | 0 |

Для повторных прогонов используйте адрес вида `demo-fsp-winner+<уникальная-метка>@example.com`. Сервер создаёт для него отдельный ID с UUID текущего аккаунта и фиксированной синтетической историей. Клиент не может назначить себе реальные достижения. У всех адресов сначала нужно подтвердить локальное письмо в Mailpit и сохранить профиль с согласием обработки.

Нажмите «Связать профиль» на `/candidate/fsp`: форма уже содержит допустимый собственный ID. Затем скачайте PDF профиля и откройте подбор работодателя. Для проверки отказоустойчивости задайте `FSP_REGISTRY_AVAILABLE=false`, пересоздайте API и обновите страницу; удаление связи продолжает работать. После демонстрации верните `true`.

## Будущая интеграция

`FspRegistry.owned_identity` и `verify_owner` изолируют источник и проверку владения. `SqlAlchemyFspRead` предоставляет общий `FspRead` для профиля, PDF и ranking. Для настоящего реестра потребуется адаптер официального источника и проверенная связка issuer/sub через авторизацию ФСП ID (ориентир ТЗ — Keycloak). Совпадения введённого ID или непроверенного email недостаточно. DTO `source=registry` предусмотрен, но внешний адаптер в MVP не установлен.
