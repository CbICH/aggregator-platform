# Блок B: опрос, тестирование и подтверждённый грейд

## Что реализовано

- Обязательный опрос кандидата: отрасль, специализация, заявленный грейд, роль и стаж. Для каждой попытки сохраняется неизменяемый JSON-снимок опроса; сам опрос не назначает категорию.
- Шесть категорий: `backend` и `qa`, уровни `junior`, `middle`, `senior`.
- 18 серверных шаблонов: по три семейства на каждую категорию. В одной попытке выдаётся по одному заданию каждого семейства с весами 40, 35 и 25 баллов.
- Вариант задания создаётся на сервере по случайному seed. В API не выдаются seed, эталонный ответ и рубрика.
- Серверный срок попытки 25 минут, сохранение черновика, восстановление без нового таймера и идемпотентный `submit`.
- Проходной результат: не менее 70 из 100 и не менее половины баллов в первых двух критических семействах.
- Отдельное явное подтверждение успешной попытки создаёт `VerifiedCategory`, историю смен и подтверждённые навыки. Неудачная попытка не понижает текущую категорию.
- Ограничения: одна активная попытка на специализацию и цель (частичный уникальный индекс), максимум три старта за 24 часа, повтор проваленного уровня через 24 часа, смена подтверждённой категории через 90 календарных дней. Старты и подтверждения блокируют запись кандидата на время PostgreSQL-транзакции.

## API

| Метод | Назначение |
|---|---|
| `POST /api/v1/candidate/surveys` | Сохранить обязательный опрос |
| `GET /api/v1/candidate/surveys` | Получить собственную историю опросов |
| `POST /api/v1/assessments` | Создать или возобновить попытку |
| `GET /api/v1/assessments/{id}` | Получить собственную попытку без эталонов |
| `PUT /api/v1/assessments/{id}/answers` | Сохранить структурированный черновик |
| `POST /api/v1/assessments/{id}/submit` | Один раз оценить попытку; повтор вернёт тот же результат |
| `GET /api/v1/candidate/assessments` | Получить собственную историю |
| `GET /api/v1/candidate/category` | Получить подтверждённую категорию и предварительный результат |
| `GET /api/v1/candidate/category/history` | Получить собственную историю подтверждённых категорий |
| `POST /api/v1/candidate/category/confirm` | Явно назначить категорию по успешной попытке |

### Контролируемый пилот B09

| Метод | Назначение |
|---|---|
| `GET /api/v1/candidate/pilot` | Получить собственный статус участия без баллов и ручного грейда |
| `POST /api/v1/candidate/pilot/join` | Вступить по одноразово созданному оператором коду приглашения |
| `POST /api/v1/candidate/pilot/attempts` | Открыть назначенную сервером форму A или B после ручной оценки |
| `GET/PUT /api/v1/candidate/pilot/attempts/{id}` | Получить или сохранить только свою незавершённую форму |
| `POST /api/v1/candidate/pilot/attempts/{id}/submit` | Отправить полностью заполненную форму без раскрытия результата |

Операторские команды `apps/api/scripts/pilot.py` создают приглашение с лимитом набора 6, 7 или 8 человек, сохраняют одну экспертную либо две независимые ручные оценки до форм, документируют разрешение расхождения, выполняют подсчёт двух отправленных форм и экспортируют анонимизированные CSV/metadata. Они намеренно не являются HTTP endpoint-ами. Полный порядок и граница фактической валидации описаны в `docs/assessment-pilot.md`.

Все изменяющие методы требуют подтверждённую роль кандидата, сессию и CSRF-заголовок. Неверный или чужой идентификатор попытки отвечает `404`, не раскрывая данные другого пользователя.

## Интеграционный контракт

Модули C и D получают подтверждённую категорию только через порт `AssessmentRead` из `app.contracts.ports`. При создании приложения реализация B `SqlAlchemyAssessmentRead(session_factory)` публикуется как `app.state.assessment_read`; модуль C получает этот read-only порт, а не write-модели B. Метод `get_verified(candidate_id)` возвращает `VerifiedCategory` либо `None`; в DTO входят категория, версия оценки, итоговый балл и доказательства навыков, но не ответы, seed или рубрика.

## Проверка

`validation/assessment-template-report.json` содержит результат проверки 100 вариантов для каждого из 18 шаблонов. Его воспроизводит скрипт ниже. `tests/test_assessment.py` дополнительно проверяет граничные пороги, полный путь попытки, сохранение и восстановление ответов, сокрытие рубрики, срок, идемпотентный `submit`, подтверждение категории, доступ чужого кандидата, суточный лимит, 24-часовой повтор, 90-дневный cooldown и изолированный поток пилота A/B без баллов в API участника.

Запуск:

```powershell
Push-Location apps/api
$env:PYTHONPATH='.'
..\..\.venv\Scripts\python.exe -m pytest tests -q --basetemp ..\..\.pytest-tmp
Pop-Location
```

Генеративный отчёт:

```powershell
$env:PYTHONPATH='apps/api'
.\.venv\Scripts\python.exe validation/assessment-template-check.py
```

## Ограничение прототипа

Рубрика оценивает только структурированные ответы. Она не подтверждает весь профессиональный опыт и не исполняет пользовательский код. Порог 70/100 и веса являются зафиксированной гипотезой MVP; реальные результаты пилота должны быть собраны по протоколу из `docs/assessment-pilot.md` до изменения порогов.

## Резерв B11

Резерв использован на исправление качества: результат неудачной попытки сохраняется после перезагрузки интерфейса, порог и критические семейства имеют отдельные граничные тесты, а кросс-модульное чтение вынесено из HTTP-роутера в `SqlAlchemyAssessmentRead`. Объём категорий и семейств не сокращался.
