# Протокол внешней валидации блока B

Этот файл не содержит вымышленных результатов. Пилот с людьми требует добровольцев и не может быть заменён автоматическими тестами.

## Что поддерживает приложение

Контур пилота реализован отдельно от обычной аттестации. Участник входит только по приглашению, использует обычную подтверждённую учётную запись кандидата и проходит две формы в зафиксированном сервером порядке A/B или B/A. Пилотные попытки не создают `VerifiedCategory`, не попадают в публичную историю и не доступны модулям C/D.

Сервер не показывает участнику ни балл, ни эталон, ни рубрику после первой формы. Автоматический подсчёт выполняет только локальная операторская команда после двух форм и уже записанной ручной оценки. HTTP API не предоставляет экспорт, изменение ручной оценки или доступ к ответам другого участника.

## До начала

1. Собрать 6-8 добровольцев с разным опытом и получить согласие на участие в оценке прототипа.
2. Для каждого участника зафиксировать самостоятельную оценку опыта и независимую ручную оценку по [короткой рубрике](../validation/assessment-pilot/manual-review-rubric.md). Не использовать эту оценку для итогового грейда в продукте.
3. Для одной специализации подготовить две сопоставимые формы: A и B. Половина участников начинает с A, половина с B. Не показывать ответы между попытками. При создании набора выбрать размер 6, 7 или 8: сервер прекращает регистрацию при этом количестве и чередует порядок A/B.

Операторские команды ниже запускаются из `apps/api`, чтобы использовать ту же локальную БД, что и API. Создайте приглашение. Код выводится один раз; не помещайте его в публичный чат или Git.

```powershell
Push-Location apps/api
$env:PYTHONPATH='.'
..\..\.venv\Scripts\python.exe scripts\pilot.py create --specialization backend --target-grade middle --max-participants 8
```

Каждый доброволец регистрируется и подтверждает email как обычный кандидат, открывает `Пилот A/B` и вводит код приглашения. После вступления приложение покажет только псевдоним вида `P-...`. Координатор получает этот псевдоним. До запуска первой формы эксперт или каждый из двух независимых рецензентов отдельно сохраняет свою оценку. Код рецензента является служебным псевдонимом, а не ФИО:

```powershell
..\..\.venv\Scripts\python.exe scripts\pilot.py record-manual-review `
  --invite-code '<код-приглашения>' --participant-code 'P-...' `
  --reviewer-code 'reviewer-1' --manual-grade middle

..\..\.venv\Scripts\python.exe scripts\pilot.py record-manual-review `
  --invite-code '<код-приглашения>' --participant-code 'P-...' `
  --reviewer-code 'reviewer-2' --manual-grade middle

..\..\.venv\Scripts\python.exe scripts\pilot.py finalize-manual-review `
  --invite-code '<код-приглашения>' --participant-code 'P-...' --reviewer-count 2
```

При единогласной оценке итоговый грейд получается автоматически. При расхождении до старта формы зафиксируйте выбранный после обсуждения грейд и причину; без причины разблокировка невозможна:

```powershell
..\..\.venv\Scripts\python.exe scripts\pilot.py finalize-manual-review `
  --invite-code '<код-приглашения>' --participant-code 'P-...' --reviewer-count 2 `
  --resolved-grade middle --resolution-note 'Сверили ответы по общей рубрике и зафиксировали уровень.'
```

После этого участник обновляет страницу и проходит обе формы подряд. На каждую форму действует серверный срок 25 минут; пропуск или истечение не перезапускаются, а должны быть явно внесены в исключения при экспорте.

Когда обе формы отправлены, оператор выполняет автоматический подсчёт. Эта команда не выдаёт результаты участнику:

```powershell
..\..\.venv\Scripts\python.exe scripts\pilot.py review `
  --invite-code '<код-приглашения>' --participant-code 'P-...'
```

После проверки всех завершённых пар сформируйте CSV и метаданные. Если кто-то не завершил обе формы, перечислите его код и причину через `--exclude 'P-...=причина'`; без этого экспорт остановится, чтобы не потерять наблюдение молча.

```powershell
..\..\.venv\Scripts\python.exe scripts\pilot.py export `
  --invite-code '<код-приглашения>' `
  --csv ..\..\validation\assessment-pilot\raw_results.csv `
  --metadata ..\..\validation\assessment-pilot\metadata.json `
  --exclude 'P-...=истёк серверный таймер' `
  --manual-review-method 'Два независимых участника команды до автоподсчёта.'
Pop-Location
```

## Сырые данные

Шаблон для анонимизированных строк лежит в `validation/assessment-pilot/raw_results.csv`, метаданные форм и исключений — в `validation/assessment-pilot/metadata.json`. Операторская команда генерирует их только из полностью проверенных A/B-пар. В них нет ФИО, email, ответов, seed, рубрик или кодов рецензентов. Для каждого исключённого кода метаданные содержат обязательную причину. Один код добровольца соответствует двум формам A/B; `manual_grade` получается только после неизменяемых независимых записей до просмотра результатов теста. Грейд ручной оценки преобразуется в ожидаемое прохождение относительно `target_grade`, поэтому расчёт согласия не зависит от заявленного грейда кандидата.

| Код участника | Специализация | Порядок форм | Ручная оценка | Балл A | Балл B | Время A | Время B | Замечание |
|---|---|---|---|---:|---:|---:|---:|---|
| Заполняется после пилота | | | | | | | | |

## Расчёт и публикация

- Указать размер выборки, даты, версии шаблонов и все исключённые наблюдения.
- Сравнить распределения баллов A/B, долю прохождения и согласие с ручной оценкой.
- Отдельно описать ограничения: малая выборка, добровольный отбор, отсутствие проверки внешней помощи и невозможность обобщить результат на весь рынок.
- Новую версию порогов публиковать только вместе с обоснованием, датой и версией рубрики.

После внесения строк выполнить из каталога `validation/assessment-pilot`:

```powershell
python analyze.py --input raw_results.csv --metadata metadata.json --output report.json
```

Скрипт проверяет формат, дубли кодов, документированную ручную оценку и зафиксированные исключения; рассчитывает размер выборки, баланс порядка A/B, распределения баллов и времени, доли прохождения, медианную разницу форм, согласие решений, наблюдения возле порога, согласие с ручной оценкой и разведочную дискриминативность групп. В `protocol_checks` отдельно фиксируются диапазон выборки 6–8, баланс порядка и ориентиры `≤10` баллов / `≥80%`; это проверяемые факты отчёта, а не объявленные заранее результаты. При пустом шаблоне создаётся отчёт со статусом `not_measured`; это честное состояние, а не результат пилота.

## Граница готовности

Код и протокол делают пилот контролируемым и воспроизводимым, но не заменяют 6-8 реальных добровольцев. До получения их согласия, ручных оценок и завершённых форм `metadata.json` остаётся со статусом `not_measured`, а B09 нельзя считать измеренно завершённой.
